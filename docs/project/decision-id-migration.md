# Decision-ID migration — 2026-09-20

Until 2026-09-20 the formal development numbered its design decisions
`D-01 … D-130`, in the order they were written, in one ledger, and listed its
open questions as bullets. The numbers grew phase by phase and served the
exploration; they also formed a second numbering universe beside production's
`ADR-NNNN` / `PRP-NNNN` / `ISS-NNNN`, with no stated relation between the two.
On 2026-09-20 the records were renamed under one policy
([governance.md](governance.md) § IDs):

- **`FVD-NNNN`** — a formal design decision: one record per choice, sequential,
  append-stable, never renumbered. The number says nothing about a phase; the
  phase is metadata (`phase:`). The old ledger entries kept their sequence
  number (`D-07` → `FVD-0007`) so that every citation in a commit message, an
  archived document or a conversation can be followed by hand.
- **`FVI-NNNN`** — a formal open item, likewise.
- **`production:`** — every record names the production record that decided,
  proposed or raised the same architectural question, with the relation
  `supports` (the formal result backs an accepted ADR), `audits` (the formal
  result audits a proposal) or `bears-on` (the formal result speaks to an open
  issue). Current documents cite the two together — `ADR-0032 (FVD-0118)`,
  `PRP-0001 (FVD-0121 … FVD-0130)` — so that one architectural fact has one
  production identity and its formal evidence beside it, and no competing number
  is minted for a fact production already names. A record with no production
  counterpart is _FV-only_.

The old numbers appear nowhere in current documents except this page, the
`legacy-id` field of each record, and archived material, which is not rewritten
(`paper/archive/`, the dated entries of `paper/NOTES.md`, commit messages). The
production repository's records (`formal-correspondence.md`, ADR-0024, ADR-0025,
`status.md`) cite the old numbers as of production `de8154f`; they are
production's to update and this table resolves each.
